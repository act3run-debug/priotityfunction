# tracker-support-unique-priority-system — fix 2026-11-02

Починка функции Yandex Cloud Functions `d4eio0bqlv9h1rvnrbna` (`tracker-support-unique-priority-system`),
которая считает поле «Уникальный приоритет» для задач очереди **TRACKERSUPPORT** (доска 214) и вызывается триггером 462.

## Что было сломано

- Функция брала задачи **активного спринта** доски 214, но доска стала канбаном:
  `GET /v3/boards/214/sprints` → 400 «У доски этого типа не может быть спринтов» → функция молча
  отвечала «Нет активного спринта. Пропуск.» и ничего не пересчитывала.
- В очереди появились тип **«Технологическая»** (`technological`) и статус **«Ответ получен»** (`otvetPolucen`),
  которых не было в настройках коэффициентов.

## Что изменено (версия `d4efrrnbd79sii8r8nqe`, 2026-11-02T13:36Z)

1. **Канбан-фолбэк**: если у доски нет активного спринта, берутся все задачи очереди из конфига
   (`BOARD_CONFIGS["214"]["queue"] = "TRACKERSUPPORT"`); игнорируемые статусы отсекаются в коде, как и раньше.
2. **Неизвестный тип задачи → приоритет 0**: типы, которых нет в `TYPE_COEFFS` (например «Технологическая», Epic),
   получают `uniquePriority = 0` (уточняющий коэффициент не прибавляется).
3. **Статус «Ответ получен» = «В работе»**: `STATUS_COEFFS['ответ получен'] = 5`.
4. Анти-шторм: PATCH только если значение действительно изменилось (триггер 462 вызывает функцию на каждый
   `Event.update` очереди — без этого правки порождали бы лавину событий).
5. Диагносика: в логи пишутся HTTP-коды неудачных запросов, в ответе — `zeroed_count`.
